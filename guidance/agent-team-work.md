## Picking the right models for workflows and subagents

Rankings, higher = better. Cost reflects what is practical in this setup, not provider list price. Intelligence is how hard a problem the model can handle unsupervised. Taste covers UI/UX, code quality, API design, and copy.

| model | cost | intelligence | taste |
|-------|------|--------------|-------|
| `gpt-5.6-sol` via Codex CLI | 9 | 8 | 5 |
| Claude Sonnet via Agent/Workflow model | 5 | 5 | 7 |
| Claude Opus via Agent/Workflow model | 4 | 7 | 8 |
| Claude Haiku via Agent/Workflow model | 2 | 3 | 3 |

How to apply:
- These are defaults, not limits. If a cheaper model's output does not meet the bar, rerun or redo the work with a stronger model without asking. Judge the output, not the price tag.
- Cost is a tie-breaker only; for anything that ships, intelligence > taste > cost.
- Bulk/mechanical work (clear-spec implementation, data analysis, migrations): use `gpt-5.6-sol` through Codex. It is the default in `~/.codex/config.toml`.
- Anything user-facing (UI, copy, API design) needs taste >= 7. Use Claude Sonnet/Opus for taste-sensitive passes, or pair Codex implementation with a Claude review.
- Reviews of plans/implementations: use Claude Sonnet/Opus for taste and architecture, and `codex review` for an independent implementation review.
- Never use Haiku for work that ships.
- Mechanics: Codex is reachable through `codex exec` and `codex review`. `CODEX_HOME` is `~/.codex`; the active config is `~/.codex/config.toml` and currently defaults to `model = "gpt-5.6-sol"`, `model_reasoning_effort = "xhigh"`, `approval_policy = "never"`, and `sandbox_mode = "danger-full-access"`.
- A repo can also carry a project-local Codex environment file at `<your-repo>/.codex/environments/environment.toml`; it is autogenerated and should not be edited manually.
- When invoking Codex from Claude, pass the repo path explicitly: `codex exec -C "<your-repo>" "<self-contained prompt>"`. For investigation-only work, add `-s read-only`.
- For local change review, use `codex review --uncommitted` from the repo root. For branch/base comparison, use `codex review --base dev` for normal feature work or `codex review --base main` for dev-to-production promotion.
- Claude models run via the Claude Agent/Workflow model parameter. `gpt-5.6-sol` does not run through that parameter; use a thin Claude wrapper when a workflow or subagent needs Codex.

Using `gpt-5.6-sol` inside workflows and subagents:
- Spawn a thin Claude wrapper agent whose prompt asks it to write a self-contained Codex prompt, run `codex exec` via the shell with `-C "<your-repo>"`, and return Codex's final answer plus any changed files.
- For review wrappers, run `codex review --uncommitted`, `codex review --base dev`, or `codex review --base main` with the review instructions as the prompt.
- Prefer Codex for implementation, mechanical edits, repo-wide searches, and independent reviews; prefer Claude Sonnet/Opus for taste, product judgment, final wording, and Claude-native orchestration.
